# North Star and MVP

## North Star

DeliveryOS makes bounded delivery work independently understandable, permission-safe, reviewable, and reproducible across repositories without centralising product ownership.

## V1 MVP

V1 provides a coherent mechanics layer:

- issue-as-contract and feature-centred delivery;
- explicit roles, authority, permissions, trust, evidence, review, and change control;
- exact accepted version and commit pinning;
- additive local overlays and reproducible pinned snapshots;
- standard issue forms and goal/review/merge templates;
- machine-readable project and feature contracts;
- standard-library conformance with accepted and rejected examples.

## Boundary

DeliveryOS does not define any pilot's product North Star, MVP, architecture, roadmap, backlog, domain gates, code, data, runtime, or release decision. Those remain local even when a project adopts shared mechanics. There is no combined product backlog.

## Coherent features

Delivery is organised around coherent user or operator value, not disconnected technical fragments. A feature issue remains the contract from discovery through acceptance. Fixes needed to satisfy its frozen acceptance stay inside that feature. Unrelated improvements become follow-up issues.
